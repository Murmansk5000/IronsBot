# B站直播预告与直播提醒

Status: completed implementation and verification (2026-11-17).
Public main is not published; production is not deployed by this work.

## Target

所有配置账号共用一套平台无关的直播监控。动态正文补全后识别自己的直播预告，
相对时间以动态发布时间及北京时间解释。直播预告是动态内容分类，默认开启；
直播提醒是独立订阅，包含提前10分钟及确认开播两次通知。赛尔号默认开启直播提醒，
其他账号默认关闭；会话直播总开关默认开启。关闭动态推送不停止解析预告。

直播总开关与各账号直播提醒沿用正文、图片的会话管理权限：群主、群管理员及超管
可以修改，普通群成员只读；私聊本人管理已授权订阅。菜单和实际修改前均复查权限，
不新增“全部推送”开关，动态提醒的群聊超管限制保持不变。

原帖与自转发都可提供预告，但转发必须可靠确认转发者和原作者UID相同。只解析
本次转发正文及发布时间，不借用原帖时间或文字；转发他人及原作者未知时不建立
直播预告。原帖与自转发的同一开播时间共用场次及通知去重，不重发已送达提醒。
赛事分类不应仅凭单独的“直播”匹配；真正的赛事直播可以同时保留赛事和直播预告。

动态普通轮询和2/5/10/30秒加强检查提供兜底机会，不创建另一套固定10分钟轮询。
预告前10分钟至预计时间后10分钟每60秒检查；开播后持续检查至两次成功观测下播。
首次观测正在直播仅建立基线，不补发旧开播通知。失败不是下播，失败退避最多5分钟。

公共outbox持久记录逐目标回执，成功不重发，不确定不盲目重试。恢复前重新核验
直播订阅、权限、路由和新鲜直播状态；不能取得状态时等待，不把暂时失败当作退订。
提前提醒不晚于预计时间，开播通知最多保留30分钟。没有订阅目标时不额外请求直播。

## Boundary

适配器只读取直播HTTP响应及发送公共消息。直播账户状态、场次和待投递通知保存在
专用SQLite，状态与新通知同事务提交；回执继续由公共投递存储拥有。账号显式偏好
复用现有按统一会话主体保存的布尔偏好（保留键`__live_reminder__`），身份合并沿用
现有存储规则；这不是动态内容分类。直播预告分类使用独立`live_preview`标识。

不新增TOML，不读取预约卡片，不使用AI/OCR，不向生产发送测试消息。没有部署授权。
