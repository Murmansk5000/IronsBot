# 统一错误定位与脱敏诊断

Status: completed (2026-11-21).
Contract: baseline extension; no authorization, retry, configuration or schema changes.

## Contract

管理错误使用公共诊断模型及模板：错误编号、北京时间、机器人、可信会话/操作者、
脱敏指令、消息摘要、操作及失败阶段。未知身份明确说明，仅访问本地映射，不联网补查。
仅显示已识别的群聊指令摘要，不转发私聊/AI正文、凭据、签名URL或完整OpenID。
后台任务显式提供任务/目标，不借用无关请求；预期业务拒绝不升级为异常。
渲染保留原始异常位置、耗时、预算及可证明的子步骤，不把包装位置冒充根因。
各机器人/会话/操作独立限频；重复统计与日志共用编号，告警失败不得递归。

## Acceptance

核对命令、菜单/延迟、素材/渲染、AI、推送、同步、连接及启动入口。
验证双平台、映射缺失、隐私脱敏、并发/后台隔离、错误回执、超时及告警失败。
只读核查2026-11-20 23:17历史日志，无法证明的来源不猜测。
隔离运行专项/完整pytest、Ruff、BasedPyright、compileall、静态及差异检查。

## Entry Audit

| 入口 | 公共诊断接入及保留规则 |
| --- | --- |
| 双平台命令、菜单和延迟回复 | 公共错误报告器；独立诊断作用域随回复恢复，不替换请求对象，不改变认领/冷却/计费 |
| 发送与回执失败 | 沿用真实SendResult，增加来源；保留HTTP/错误码/接口/合法Trace ID，不虚构调用栈 |
| 渲染与素材失败 | 原始位置、耗时、预算；素材请求/校验解码与排队/原生合计步骤；未知步骤不推测 |
| 上次原生渲染中断 | 崩溃标记保存脱敏原始诊断；重启后报告上次任务，不借用当前用户消息 |
| AI聊天与启动API检查 | 聊天来源仅定位、不转发聊天正文；提供商异常正文不直接拼入通知；正常检查通过保持原样 |
| B站动态及私聊主动投递失败 | 后台任务、动态ID、逐目标稳定摘要及本地可信映射；原阶段/回执/订阅规则保留 |
| B站登录错误 | 二维码申请、凭据不完整、登录轮询错误显式标记；正常二维码和成功提示不包装为错误 |
| 游戏连接 | 启动登录失败及离线状态标明游戏账号和检测来源；正常上线、维护通知不升级为异常 |
| 数据同步与时钟 | 启动同步实际失败、启动时钟偏差警告使用后台诊断；正常更新/同步/时钟成功不变 |
| 身份关联冲突 | 使用真实规范化事件及本地映射，不额外请求群/用户信息 |

原始入口尚未提供消息时明确写“入口未提供”，不借用同一用户的其他消息。
身份别名来自配置和可信映射；未缓存的群名/昵称不联网补查，未知显示摘要。
命令错误按机器人/会话/操作/错误位置独立60秒限频，并由应用任务所有者发送重复汇总。
其余业务保留原有去重、限频及订阅语义；诊断不新增推送目标或业务重试。
通知最多预览8个任务目标并限制文本长度，完整目标标签用同一错误编号写入日志。
