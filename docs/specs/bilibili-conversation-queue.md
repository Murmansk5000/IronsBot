# B站动态按会话持久排队

Status: completed (2026-11-19). Baseline delivery correction.

## Contract

同一投递会话跨B站账号FIFO，前一条动态及其有限重试结束才执行下一条；其他
会话不等待。以平台、账号及规范化会话标识隔离实际投递地址，不猜测跨账号映射。
同轮沿用现有发布时间升序，后发现的内容追加；队列登记先于后台发送及检查点推进。
队列序号、等待、执行、离线挂起、不确定阻断和结束状态持久化，启动幂等迁移。

排队不占发送并发、不启动60秒期限、不增加次数，不被误标为跳过或成功。每会话
当前动态继续沿用4次/60秒和2/5/10秒退避。确定失败允许后续；离线挂起本会话；
结果不确定阻断本会话，可靠迟到回执或原有24小时有效期结束后才能放行，不能重开
旧动态已终止的后续阶段。正在发送的任务在结束或租约失效前不因过期而抢占。

首发、恢复、重连和启动共用登记、头部筛选与持久认领。每个目标完成即唤醒其
后继，不等其他群完成。媒体准备仍按动态共享，权限/订阅/路由仍在实际执行复核。
不变更长期架构目标、不新增TOML、不修改原有消息格式及图片质量。

## Verification

双平台覆盖同会话跨账号/跨轮多动态，其他会话并行，重试期间不插队，离线恢复、
迟到回执、过期、退订、重启、认领竞争及取消。断言排队不计费、不耗预算、不准备
媒体、不误记成功；启动迁移不重发已成功或不确定消息。
使用隔离检出中的已提交预留模块运行完整pytest、Ruff、BasedPyright、compileall、
仓库静态及差异检查。原始记录不足以追溯的历史合图原因不推测。

## Implementation and Evidence

`conversation_queue` 将每个冻结目标的序号与状态保存至原B站投递账本；
幂等启动回填只引用原阶段，不重置回执、次数或时间。首次登记在监控任务生成前
完成；队首筛选和动态租约在同一写事务中校验，阶段认领还复核当前会话执行权。
现有动态重试只迭代本次认领目标，队列等待不进入发送批次或媒体准备。

目标结束及可靠迟到回执均唤醒可执行队首，后台任务使用现有应用任务所有者。
离线只挂起当前未完成阶段，保留已有准备失败证据和预算；恢复时不把图片父阶段
误当成已提交。路由变更不重定向旧任务，过期只结算未提交阶段，不改写成功/不确定
回执；实际发送中且租约有效的目标不会被过期任务抢占。

扩大专项覆盖全部B站测试及架构约束；不确定回执测试先等待进入传输，再通过账本
到期接口注入故障，不依赖30毫秒以内的机器调度。最终完整验收及各检查退出码见
`E:/IronsBot-history-validation/bilibili-conversation-queue-20261119/latest-all.json`。
