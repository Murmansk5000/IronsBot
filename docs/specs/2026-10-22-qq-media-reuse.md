# QQ 官方同账号跨群媒体复用

[返回平台说明](../qq-platform-guide.md)

## 目标与规则

同一条 B站动态的并发目标共用已准备的图片。同一 AppID、同一群聊／私聊类型、同一素材指纹
及文件扩展名只执行一次成功上传，不同账号各自上传。每个群仍独立调用消息接口、取得回执、
记录逐图账本、判定失败和执行已有安全重试。

媒体复用作用域覆盖本次动态投递及其重试轮次，结束即清理，不持久保存或猜测平台凭据有效期。
新的动态、独立调用和重启恢复创建新作用域。普通被动图片查询维持现有上传行为。
相同 URL 只在当前作用域复用；二进制内容按 SHA-256 区分，不按文件名猜测内容相同。

上传通过共享任务合并；取消一个等待者不取消其他等待者的上传。上传失败不缓存为成功，
后续安全尝试可重新上传。作用域退出时取消并等待剩余上传任务，清理临时文件。
消息提交失败不会使其他群已完成的记录失效；结果不确定不自动重发，也不通过换账号兜底。

2026-10-22，在 public_bot 的 admin 与 robot 两个已有可信群地址上完成隔离测试：

| admin | admin | 初次上传 | `2b948025f169` |
| admin | robot | 否，复用 | `2ab448944a23` |
| robot | robot | 第二张测试图初次上传 | `128f005ab860` |

两张不同标记的小 PNG 共上传 2 次、消息提交 4 次，全部返回独立消息 ID。
测试使用直接 API 验证跨群凭据复用，没有修改业务库、重放历史动态或替换生产代码。
此证据不宣称跨 AppID、跨群聊与 C2C、长期缓存或所有文件类型均受平台保证。

## 本地回归

- 并发群共享上传、不同 AppID 和聊天类型隔离、不同图片隔离、作用域结束重新上传。
- 上传失败后安全重试，等待者取消与整次投递取消的任务／临时文件清理。
- 真实 B站发送协调器、QQ SDK 消息适配及 SQLite 账本组合：成功群只提交一次，
  限流拒绝只重试失败群，响应丢失记录不确定且不重发，恢复运行不重复成功项。

凭据只存在内存，不输出 file_info、Secret、OpenID 或签名 URL。日志使用执行 AppID、素材指纹和现有投递单元定位。
本次实现不自动部署，也不为旧版缺少逐图回执的失败动态补发。
