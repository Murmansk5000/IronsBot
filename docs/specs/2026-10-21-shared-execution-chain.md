# 双平台完整执行链收口

状态：进行中。此目标不等于此前菜单统一已经全部验收。

## 目标与验收范围

输入统一为 `MessageInputContext`；公共层拥有身份合并、路由、权限、目标解析、菜单、认领、冷却、判重、额度、查询、渲染、异常及完成/失败释放。平台只转换协议、收发消息与回执。主项目与私有 main/details 都必须验证真实注册入口和副作用；不得只证明同名业务函数存在。

保留功能及既有工作区，不推送、不部署。私有 details 当前有大量并行修改，仅核验，不把它们混入本步提交。私有 main 的未跟踪 uv.lock 保留。最终扩展配对须在公共最终提交冻结后重新验证。

本步将静默拒绝明确表达为 None，不再构造永远不会发送的“重复请求”回复。玩家目标、绑定确认、扩展与菜单回调同步声明可无结果；无结果不伪造成功，不刷新原菜单等待期。已有绑定确认若真正修改了绑定，仍返回实际绑定状态，不把这个副作用隐去。

直接命令和解析后目标现在复用同一个请求占用/结算实现。取消、异常、业务失败、投递失败会释放；只有成功执行并送达后记录完成。完成回调幂等，回调失败不能留下成功记录或锁。

## NoneBot 移除评估

结论：不把保留 NoneBot/matcher 作为设计条件。可以移除，但不能只替换 WebSocket 接收函数就宣称完成。

基线 AST 检索发现 71 个生产模块直接导入 NoneBot：根入口 1、app 6、integrations 22、plugins 42。这是当时的依赖分布证据，不是当前文件数或运行时注册数量。基线中的 scheduler 生命周期依赖已于第四十步移除，私有插件依赖于第七十八步移除，内置插件依赖于第七十九步移除；htmlkit 和应用宿主的框架依赖仍存在。

替换必须覆盖：

- 应用自己持有 ASGI、启动/关闭和资源顺序，官方单平台不再为启动而初始化 NoneBot。
- OneBot 反向 WebSocket 的鉴权、多连接、echo 请求/回执关联、断线取消、消息/通知转换与重放保护；消息交给同一个公共路由，不另建一套命令分发器。
- 显式组合根注册公共与私有贡献；删除依赖 NoneBot 的元数据/加载路径，不提供旧路径 re-export。
- 已完成：应用直接持有 AsyncIOScheduler 的生命周期，保留任务语义与业务持久状态；真实关闭会等待受管作业退出。
- 当前 HTML 引擎是 litehtml 原生扩展，不是浏览器；后续字体初始化、资源获取和引擎任务生命周期不再借助 NoneBot 插件，业务展示和模板不因此重写。
- 保留戳一戳、入群、审核、连接观察等非命令事件，分别按公共业务与协议边界归属迁移。

调度器资源已独立，其余迁移要求尚未全部实施，不得据此删除当前运行入口。只有同一公共执行链覆盖全量功能及三种部署模式后，才能切换并删除旧入口，不能长期保留双轨开关。
